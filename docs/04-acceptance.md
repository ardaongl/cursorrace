# Acceptance and evidence map

These eight criteria remain the normative verification contract. Executed local outcomes are recorded in docs/BUILD-EVIDENCE.md and docs/REPO-FACTORY-STATUS.json; the table defines requirements, not self-proving evidence. Assertions must use hand-authored expected values, never call checker internals to compute expected results. Each unittest class name is a required traceability anchor; test methods expand the listed partitions. No AC can be marked PASS merely because metadata validation passes.

| ID | Observable requirement and failure boundary | Independent tests / fixtures | Later command; expected result |
|---|---|---|---|
| AC-01 | Frozen snapshot membership despite insert/delete; empty dataset and empty continuation accepted. Deleted IDs stay required; newly inserted IDs stay excluded. | tests.test_oracle.SnapshotTests; pass-snapshot, pass-empty, pass-empty-continuation, fail-delete-gap, fail-unexpected | `.venv/bin/python -m unittest tests.test_oracle.SnapshotTests -v`; 0, exact goldens and product exits 0/1 |
| AC-02 | Detect duplication, rank regression, unexpected IDs and overflow, accumulating in fixed order. | tests.test_oracle.FindingTests; fail-insert-shift, fail-order, fail-multiple, fail-overflow; duplicate unknown IDs and cross-page inversion tests | `.venv/bin/python -m unittest tests.test_oracle.FindingTests -v`; 0; full ordered findings equal independent expectations |
| AC-03 | Cursor equality/continuity, cycles, post-terminal events and incomplete traversal; absence reported only with terminal final page. | tests.test_traversal.TraversalTests; fail-chain, fail-cycle, fail-incomplete, fail-after-terminal; first non-null request, multiple terminal pages, cycle across mutations | `.venv/bin/python -m unittest tests.test_traversal -v`; 0, exact findings/pointers and no speculative missing |

Full gate: `.venv/bin/python -m unittest discover -s tests -v` then both module gates, all exit 0. Individual failures must remain failures; a harness that hides nonzero unexpected product exits fails acceptance.

Evidence format per executed check: UTC timestamp plus client date, command and CWD, exit code, CPython/pip/OS, captured stdout/stderr path, fixture SHA-256, candidate tree fingerprint excluding generated artifacts, and observed vs expected assertions. Keep raw logs under `.local-verification/`; record summaries/references in IMPLEMENTATION-STATUS.md and acceptance evidence arrays in REPO-FACTORY-STATUS.json. Do not store tokens or real production IDs in evidence. Planned evidence is not execution evidence.

Hosted CI repeats these local gates on Ubuntu 24.04/CPython 3.14.8 after an authorized push. Matching final SHA and hosted run URL belong to release attestation, separate from AC local PASS. CI creation/execution and independent audit are later phase obligations.
