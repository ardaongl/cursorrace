# Verification design

The commands and harnesses specified here are implemented; actual results are recorded separately in BUILD-EVIDENCE.md and local raw evidence. stdlib unittest is the runner; meaningful behavior partitions replace an arbitrary line-coverage percentage. Every public code, parser boundary and output channel must be exercised. Passing these cases still does not waive separate audit.

## Independent oracle and test layers

Use explicit ordered findings from static goldens and fresh hand-derived examples, never production functions to generate expected findings. Test arbitrary partitions of a short fixed snapshot (all ordered splits including empty pages) to verify pass invariance; manually swap/remove/repeat one identity and assert the expected defect. Include equal ranks, duplicate unknown IDs and known IDs separated by unknown IDs. Ledger assertions are independent set-transition examples. Parser tests operate on raw bytes, not only json.dumps output. Unit tests target decoder, ledger, checker, serializer; subprocess tests exercise installed console entry point and python -m cursorrace. Prevent empty test discovery from silently passing: each gate reports a positive case count and verifies expected test classes loaded.

## Required validation partitions (AC-04)

- Byte size exactly 1,048,576 accepted when otherwise valid (pad with legal whitespace); +1 rejected LIMIT. Empty file JSON error. UTF-8 BOM, invalid UTF-8 and unpaired escaped surrogate rejected. Escaped ASCII ID equal to literal ID follows decoded equality.
- Root list/null, missing/unknown keys at all levels, wrong primitive types, bool-as-int, schema versions 0/2, decimal/exponent number lexemes, NaN/Infinity, trailing content, duplicate/escaped duplicate keys, invalid syntax and braces inside strings. Depth 16 vs 17 generated as syntactically valid JSON: depth16 may then fail shape but cannot fail LIMIT; depth17 fails LIMIT before shape. No raw input echoed.
- Oversized integer lexemes: place a syntactically valid integer with more digits than CPython's default integer-conversion threshold (for example 5,000 digits) in page_size while keeping the complete input within the byte cap. Reject it as SCHEMA at /page_size under the existing numeric bounds, without INTERNAL, traceback or unbounded conversion. Include a near-byte-cap integer and distinguish malformed number syntax (JSON at root). Do not change the existing field ranges or resource limits to accommodate the test.
- Snapshot 0/10,000/10,001, duplicate snapshot IDs, IDs length 1/64/65, leading punctuation, newline, whitespace, non-ASCII and case distinctions. Test no accidental regex end-newline acceptance. Cursor null vs empty, lengths 1/256/257, punctuation, space/newline and opaque secret canary. Lexical cursor content never interpreted as a path or URL.
- Page size 0/1/1,000/1,001; events 0/1/10,000/10,001; page ids 0/1,000/1,001; aggregate occurrences 100,000 vs100,001. Build max-count cases within byte cap using short repeated IDs; max page IDs over page_size are valid input with domain overflow. Counts beyond schema maxima use SCHEMA, aggregate uses LIMIT.
- Missing page, bad event kind, extra mutation fields, insert-existing, delete-absent, double delete, delete-then-reinsert, repeated insertion and valid insert/delete. Invalid final ledger event must suppress earlier page findings. Writes before first page legal; after terminal yields AFTER_TERMINAL. Replay must not treat observed pages as source-of-truth live state.
- Deliberately combine invalidity categories to verify documented precedence, while not asserting unspecified pointer selection among same-category errors.

## Traversal/report/CLI partitions (AC-01–03,05–06)

Full and partial final pages, empty continuation, initial non-null request, next-null followed by another page or mutation, chained mismatch/cycle combinations, nonconsecutive cycle, equality at current cursor and across mutation events. Missing IDs in snapshot order only with terminal final page; with an earlier terminal and incomplete final page still no missing. Verify all finding order/pointers and stats including repeated/unexpected observations. Secret cursor tokens absent from stdout/stderr. Repeat process under changed locale/CWD to verify canonical ASCII output. Verify application-controlled filesystem behavior using the separate ordinary and bytecode-suppressed runs below; suppressing bytecode only in tests cannot establish the ordinary-run guarantee.

Arguments: no args, wrong subcommand, too many paths, unknown/repeated options, --help/--version exact forms, filenames beginning dash via --, literal file named -, whitespace paths, symlink regular file, directory/FIFO/device and unreadable/missing file. Assert fixed IO code instead of OS exception prose. Use mocked OS read failure for platforms where permission tests run with elevated rights.

Nonregular-file substitution: deterministically replace a regular input path or symlink target with a FIFO or directory between preliminary inspection and open. Verify the object actually opened is checked, nonregular content is not read, and the invocation exits 3 with INPUT_IO without blocking. Use synchronization/fault injection in the test harness and a bounded subprocess timeout; no product race-injection option. A legitimate symlink to a regular file must still work. Include the ordinary and bytecode-suppressed cold-cache cases below as regressions for execution with missing bytecode caches.

Closed-output test must close the parent's pipe before child writes and assert exit3/no traceback; include flush-only failure via controlled stream unit double. Closed stderr failure still exit3. Internal exception maps to INTERNAL with controlled dependency injection in unit test (no product CLI fault-injection feature). Controlled KeyboardInterrupt tests at main boundary assert 130; an OS-controlled subprocess signal test confirms supported macOS/Linux behavior. Do not claim hard kill guarantees.

Permanent AC-06 hardening regressions in `tests.test_cli.CliTests` additionally exercise both installed entrypoints outside the checkout: `test_closed_descriptors_in_installed_entrypoints` closes actual POSIX descriptors after subprocess pipe setup and before exec, so CPython starts with the corresponding stream set to None. It asserts input IO with stderr absent; version with stdout/both absent; pass, domain-fail and invalid-input reports with stdout absent; and validation/pass output with only stderr absent. `test_preclosed_pipe_peers_in_installed_entrypoints` removes pipe readers before launch to test buffered EPIPE on stdout, stderr and both without timing assumptions. `test_normal_streams_in_installed_entrypoints` preserves exact version/pass/fail/invalid bytes and exits. Full tuple comparisons enforce observable diagnostic categories, no traceback/INTERNAL misclassification and no fallback to stdout. Descriptor tests require POSIX and explicitly skip Windows, which is outside v1 support; macOS and Linux CI use the same deterministic setup. DEVNULL is not used to simulate a closed descriptor.

No execution-time network: deny Python socket/DNS creation in a subprocess wrapper and rerun fixtures. Pair with code inspection for subprocess/native escape paths; tracing cannot prove universal absence of side effects. Never use production data.

## Application-level no-write verification (AC-05)

These are required implementation tests; this description alone is not execution evidence. Apply the contract's application-level boundary to both installed invocation forms, successful audits (exit 0), domain failures (exit 1), invalid input/ledger failures (exit 2), and representative input IO failures (exit 3). Pre-existing input traces, snapshots and other user-data sentinels must never be modified, deleted or renamed. Harness preparation, dependency installation and output capture occur outside the audited child execution interval; harness-owned setup is not application behavior. Writes to the contracted stdout/stderr streams are permitted.

1. **Ordinary execution, including missing bytecode caches:** use a writable isolated installation with interpreter bytecode caches removed by the harness before launch. Leave PYTHONDONTWRITEBYTECODE unset and do not pass -B. Run the actual console and module entry points. Inspect the installation, CWD, input/snapshot/sentinel directories and isolated temporary/home/cache directories before and after. Only interpreter-originated import bytecode artifacts may be excluded. Attribute any __pycache__ directory, .pyc file, or CPython cache-write staging artifact to interpreter import behavior and the installation/interpreter scope; a matching filename alone is not an exemption. Reject application-controlled logs, temporary files, caches or state even when disguised with those names. Calibrate artifact classification against a known interpreter import so a permitted artifact is not incorrectly reported as an application violation; ordinary executions need not generate bytecode on every run.
2. **Optional stricter execution:** in fresh isolated installations again lacking bytecode caches, launch the console script with PYTHONDONTWRITEBYTECODE=1 already in its environment and launch the module with `python -B -m cursorrace`. Before/after inspection must find no newly created __pycache__ directories or .pyc files within the declared isolated boundary, and the application mutation guards must also pass. Compare exit codes and canonical reports to ordinary runs. Suppression does not remove pre-existing caches. Do not claim that setting sys.dont_write_bytecode after package initialization prevents earlier startup writes, or that these observations prove universal OS-level zero writes.
3. **Attempt detection:** pair filesystem inspection with direct behavioral guards/instrumentation that record and fail the test on attempted application-controlled mutations, even if the operation raises, is caught, or restores the original bytes. Cover write-capable open modes and os.open flags, file-descriptor writes/truncation, create/delete/rename/replace operations, directory mutation, and logging/tempfile/cache creation APIs used or reachable by the application. Record attempts in harness memory or a harness-owned channel, not an application log. Allow only contracted stream output and attributed CPython import-cache operations. Exercise real installed entry points plus focused boundary tests; inspect code for mutation routes outside instrumentation and report its coverage limits. No external runtime dependency is introduced.
4. **Guard calibration and input preservation:** test-only controls must deliberately attempt a forbidden write, same-bytes rewrite, create-then-delete and rename-then-restore, including application writes to bytecode-looking paths. Guards must record/reject these attempts even if final filesystem contents would match. After each audit compare input/snapshot/sentinel hashes, bytes and relevant file metadata, and enumerate added/removed/renamed paths, excluding access-time changes caused by ordinary reads. An absence of visible differences alone never proves that no writes were attempted. Repeat with both passing and failing audits; denied/caught mutation attempts still fail acceptance regardless of product exit code.

Evidence records the exact launch command/environment, observation interval, inspected paths, baseline cache state, permitted interpreter artifacts and their attribution, attempted mutation events, before/after comparisons and instrumentation limits. Application tests must not mask writes by disabling all filesystem instrumentation or broadly allowing .pyc paths. Universal host/OS activity outside this tested boundary is not covered.

## Package gate (AC-08)

`tests.package_gate` is the stdlib orchestration module for the following required checks:

1. Use a clean temporary build environment with CPython3.14.8/pip26.2.1 and download **setuptools==80.9.0** to a dedicated wheelhouse; record SHA-256 and source. This is the explicit network-permitted bootstrap step. No unpinned build library. Acquire CPython/CI tools separately if absent at preflight.
2. Install the backend from that wheelhouse with `pip install --no-index --find-links WHEELHOUSE setuptools==80.9.0`; invoke its build_meta build_sdist and build_wheel hooks using stdlib Python (no build frontend dependency). Record commands/exits and artifact hashes. Extract sdist only after rejecting absolute/parent-traversal/symlink escape paths; rebuild its wheel in another clean directory with the same backend.
3. In two fresh venvs install the original wheel and sdist-rebuilt wheel respectively using `pip install --no-index --no-deps ARTIFACT`. No source checkout on sys.path, no PYTHONPATH, CWD outside repository, no runtime network. Compare package metadata runtime dependency list to empty; verify declared Python requirement, version, schema package data and MIT license. sdist includes docs/tests/static fixtures.
4. Run `cursorrace --help`, `--version`, console and module forms against all 17 fixtures from the temporary directory; compare exact bytes/channels/exits with manifest. README demo succeeds after installed path substitution. Missing docs/schema/license or checkout-dependent imports fail gate.

Full local gate commands are listed in docs/04-acceptance.md. GitHub workflow later repeats them with immutable action references. Spec metadata validator proves only document completeness. Separate audit must design new cases for regex/parser bypass, misleading snapshot claims, output failures, clean install and README promises; merely repeating unittest is insufficient. Any fix requires affected tests and fresh independent audit on the final candidate.
